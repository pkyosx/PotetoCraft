# Exhaust the Design Space

**Apply when** you face a new UI interaction or architectural decision with no precedent in the codebase.

Do not build the first idea that comes to mind.
Produce two or three competing sketches that take different approaches, not small variations of one approach.
You can write them yourself, or hand each one to a subagent running the same model as the session. The Subagents section of [the poteto-mode skill](../../SKILL.md) says how to spawn them.
Keep each sketch cheap and disposable. A throwaway page or a short script is enough.
Name the criteria before you compare. Put the sketches side by side and judge each against those criteria.
This matters most where the result depends on how it feels to use, not only on whether the logic is right.
Pick one, and write down why the others lost.

You skipped this when the report names one design and no alternative.
You followed it when the report shows the sketches, the criteria, and the reason for the choice.
Present the choice to the user when it is a product or taste call, per [ask-only-what-only-the-human-can-answer](ask-only-what-only-the-human-can-answer.md).
